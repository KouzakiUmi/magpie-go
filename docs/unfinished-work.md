## P5 — 当前供应商余额 / 用量通知（未实现）

**目标**：每个当前启用的供应商账户各显示一条通知，不合并不同币种。

**实现要点**

- 数据来源：`GET /api/providers` 与 `GET /api/usage/quotas`（已在新版本 Magpie 实测结构）。
- 取值优先级：`balance`（余额）→ 额度窗口（5 小时 / 每周 / 每月）→ 回退 token 或消费统计。
- 通知形态：按账户独立通知，标题含供应商与账号标识（需脱敏），正文含余额或剩余比例与重置时间。
- 刷新频率：由前台服务统一轮询，避免每账户一个定时器。
- 生命周期：随网关运行状态启停；网关停止或进程丢失时清空通知，不得残留过期数据。
- 通知 ID 稳定性：以「供应商 + 账号指纹」派生固定 ID，重装或重启后不重复堆积。
- 凭据边界：通知正文不得包含 API key、web key、登录态、完整账号邮箱或订阅标识；账号只显示可脱敏后缀。

**待确认**

- 刷新间隔（建议 15 分钟级别，与网关额度更新节奏一致）。
- 是否允许用户在菜单中关闭余额通知。
- 多账号同供应商时的展示顺序。

**前置条件**：Magpie 网关已运行，且至少配置一个可读额度的供应商账户。

## P6 — APK 内更新 Magpie 内核（未实现）

**当前状态**：Magpie 自身的检查更新与自动更新入口已在 WebView 中隐藏，尚未提供替换机制。

**实现要点**

- 只使用官方 release 产物，固定 SHA-256 与签名校验。
- 新内核写入 App 私有可执行目录，不覆盖只读 `nativeLibraryDir`。
- 切换前校验 ABI（arm64）、校验与 `proot` / `loader` / `talloc` 同架构。
- 需要支持回滚：保留上一版本内核，切换后真实启动失败时自动回退。
- 切换后必须实际启动验证：健康检查通过、端口占用正确、模型发现可用。
- 失败时不得留下半配置或无法启动的状态。

**待确认**

- 是否允许用户指定版本，或只跟随最新官方版本。
- 与运行时（`files/runtime/`）更新是否共用同一界面。
- 校验失败时的用户提示与重试策略。
